# DS 工作图标 · H2「等离云核」设计规格 v1

> 本文件是**接口契约**。Node 宿主侧与 Python 窗口侧各自实现，只通过第 5 节的消息协议通信。
> 视觉常量冻结在此，实现方不得自行改色改尺寸；动效参数可调，但要保持相对关系。

---

## 1. 形态与定位

- **原生置顶窗口**（不是页面内悬浮），任意应用上层可见，像 dsh-dafeiyu 那样由宿主插件拉起一个独立进程。
- 默认图标直径 **140 px**（含能量底盘），用户可调 96 / 140 / 200 三档。
- **窗口尺寸 = 图标直径 × 1.5（即图标占窗口宽度的 66%），图标在窗口内居中。** 依据实测：Electron 在 140px 下，SVG 占 82% 时光晕仍被窗口边界裁切（`outer_frame_max_alpha=4`，即边缘有非透明像素）；调到 **66% 时外框 alpha=0**、全透明占比从 11.6% 升到 28.8%。窗口本身逐像素透明，多余边距不显示任何东西，但它是光晕的容身之处——**边距给不够，小尺寸下光晕边缘会出现肉眼可见的硬切**。
- 窗口本身无边框、无标题栏、背景**逐像素透明**——屏幕上只看得到图标，看不到窗口方块。
- 位置：默认屏幕右下角，距边 24px；可拖动，位置记忆持久化。
- 默认**不抢焦点**（点它不激活窗口、不打断你正在打字的窗口）。
- 默认**鼠标穿透**关闭区域 = 只有图标实际绘制到的圆形区域内可点，其余位置点击穿透到桌面。

## 2. 图层结构（以 200×200 视框为单位，最终按 `scale = 直径/200` 缩放）

自下而上 7 层：

| 层 | 几何 | 说明 |
|---|---|---|
| L1 能量底盘 | 圆，r=97，径向渐变 | 深色半透明底盘，解决"白底隐形"。必须在最底层 |
| L2 刻度环 | 圆，r=94，`stroke-width 1`，`dasharray 1.5 7` | 细虚线刻度，颜色 c2 |
| L3 等离子云 | 粒子群，r∈[72,97] 环带 | **本方案的主角**，见第 3 节 |
| L4 分段环 | 圆，r=60，`stroke-width 2`，`dasharray 40 16 8 16`，圆头 | 颜色 c1，随状态旋转 |
| L5 内细环 | 圆，r=48，`stroke-width 1` | 颜色 c2 |
| L6 核心辉光 | 圆，r=44，高斯模糊 11 | 颜色 c1，透明度 = `core × 0.2` |
| L7 核心 | 三角 `M100,70 L126,116 L74,116 Z` 描边 `stroke-width 2.6` + 中心圆 r=12 | 颜色 c1，透明度 = `core`。**核心恒定不变形**——这是 H2 的定义性特征 |

L1 底盘渐变（固定色，不随状态变）：

```
0%   #050809 @ 86%
82%  #050809 @ 50%
100% #050809 @ 0%
```

## 3. 等离子云（粒子）规格

粒子分布在 **r∈[72,97] 的环带**内。

> ⚠️ **本条正在 A/B 对照中，待用户拍板，定稿前不要按它改现有实现。**
> v1 规格这里有**自相矛盾**：既说"环带分布"又说"球面投影"，而球壳投影到平面得到的是**实心圆盘**、不是环带。参考实现 `halo()` 用的正是球面投影，实测粒子实际半径落在 **[4.3, 95.6]**，带内占比仅 **27.8% / 40.3% / 38.8% / 34.6%**（IDLE/THINK/WORK/WAIT）——有相当多粒子跑到核心附近。严格 2D 环带（半径不被 `cosθ` 压缩，深度用半径反推）则带内占比 ≈100%。两种分布的对照渲染图正在产出，**以用户选择为准**。

- 每颗粒子 `fill = c1`，半径 `0.85 + z×1.5`（z∈[0,1] 为深度），透明度 `0.26 + 0.74×z`。
- **粒子数、半径带、角速度随状态变化**（核心指标：粒子密度与速度 = 工作强度）：

| 状态 | 粒子数 | 半径带 | 角速度 | 云的行为 |
|---|---|---|---|---|
| 空闲 IDLE | 36 | 80–96 | 60 s/圈 | 缓慢漂移，偶发闪点 |
| 思考 THINK | 62 | 76–94 | 24 s/圈 | 稳定环绕，自转加速 |
| 执行 WORK | 98 | 72–92 | 6 s/圈 | 高速环流，云被"吸"向环面（半径带整体内收） |
| 待确认 WAIT | 52 | 80–97 | 18 s/圈 | 减速度，整云染琥珀，配呼吸脉冲 |
| 完成 OK | 98 | 72–92 | **2 s/圈** | 短暂加速（庆祝感），随 2.5s 一次性动效结束 |
| 出错 ERR | 98 | 72–92 | **0（冻结）** | 云静止不动 = 表达"卡住了"，配合抖动 |

粒子数变化用 **300ms 线性插值**过渡（不能瞬间跳数，会闪）。

## 4. 状态配色与动效

七态共用一套色语言：**只有颜色与动效变，形状永不变。**

| 状态 | c1（主色） | c2（暗色） | glow | core 透明度 | 动的部分 |
|---|---|---|---|---|---|
| 空闲 IDLE | `#3d7688` | `#1b3b47` | `rgba(80,190,220,.20)` | 0.13 | 云慢漂 + 分段环极慢转 |
| 思考 THINK | `#38e8ff` | `#176c85` | `rgba(56,232,255,.55)` | 0.42 | 自转加速，核心轻微呼吸 |
| 执行 WORK | `#5cffd0` | `#128f78` | `rgba(92,255,208,.62)` | 1.00 | 云高速环流 + 核心满亮 |
| 待确认 WAIT | `#ffb340` | `#a35a08` | `rgba(255,179,64,.62)` | 0.55 | **整图 1.9s 呼吸脉冲**（glow 6px↔20px） |
| 完成 OK | `#8dffae` | `#1f9b5a` | `rgba(141,255,174,.55)` | 1.00 | 一次性：白光闪 + 一圈扩散环，2.5s 后自动回 IDLE |
| 出错 ERR | `#ff4d6d` | `#8e0f2a` | `rgba(255,77,109,.62)` | 0.70 | 左右抖动 3 次（每次 ±2px，80ms），停在该态直到下一事件 |
| 离线 OFF | `#5a636e` | `#2b3138` | `rgba(140,150,160,.16)` | 0.20 | 粒子静止，无旋转 |

**状态切换统一 300ms 交叉淡入**，禁止硬切。

## 5. 进程间协议（冻结）

宿主 Node 进程 **spawn 一个窗口子进程**（技术栈已定案 **Electron**，见第 9 节），双向 **newline-delimited JSON over stdio**（每行一个完整 JSON，无 BOM，UTF-8）。

```jsonc
{ "protocolVersion": 1, "kind": "<kind>", "timestamp": 1757000000000, "..." : "payload" }
```

`kind` 取值与方向：

| kind | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `ready` | 窗口→宿主 | `{ pid }` | 窗口已创建，可以开始发状态 |
| `state` | 宿主→窗口 | `{ state, activity?, task?, session?, progress?, elapsedMs?, tokens? }` | **主消息**，状态变更时发 |
| `pulse` | 宿主→窗口 | `{ state, activity? }` | 心跳（默认 5s 一次），窗口 15s 未收到任何消息 → 自行转 `DISCONNECTED` |
| `config` | 宿主→窗口 | `{ scale, opacity, alwaysOnTop, clickThrough, position }` | 配置下发 |
| `setting` | 窗口→宿主 | `{ key, value }` | 用户在右键菜单里改了设置，回传宿主持久化 |
| `shutdown` | 宿主→窗口 | `{}` | 优雅退出 |
| `closed` | 窗口→宿主 | `{ reason }` | 用户从菜单选了退出 |

`state` 枚举（与 dsh-dafeiyu 一致，可直接复用其归约逻辑）：
`IDLE | THINKING | WORKING | WAITING | SUCCESS | ERROR | DISCONNECTED`

`activity` 枚举：`searching | editing | testing | commanding`

**健壮性要求**：任何一方收到无法解析的行 → 记日志并忽略该行，**不得崩溃、不得阻塞**。宿主进程退出时必须 kill 掉 Python 子进程，不留孤儿窗口。

## 6. 交互行为

- **拖动**：按住图标拖动；松开后把新位置写入配置文件。
- **悬停**：图标轻微放大到 1.06 + 显示一行状态文字（如"执行中 · Bash"）。
- **点击**：切换到浏览器里的 DSH 页面（若检测不到则忽略，不报错）。
- **右键菜单**：尺寸（96/140/200）、透明度（60/80/100%）、始终置顶、鼠标穿透、开机自启、退出。
- **待确认时**：琥珀脉冲是**唯一**允许主动吸引注意的状态；其余状态一律安安静静，不闪烁、不发声、不弹窗。

## 7. 落盘

- 配置：`%USERPROFILE%\.dsh\work-icon\config.json`（尺寸/透明度/置顶/位置/开机自启）。
- 日志：`%USERPROFILE%\.dsh\work-icon\helper.log`（滚动，上限 1MB）。
- 崩溃不得影响 DSH 主进程：宿主侧 spawn 失败要静默降级为"图标不显示"，并在日志里留痕。

## 8. 验收尺子（每条都能判定成立/失败）

1. 在白底窗口和深色壁纸上，图标都清晰可读（无黑色方块、无锯齿白边）。
2. 140px 下，站在 1.5 米外能把"空闲 / 执行 / 待确认"三态**用颜色区分开**。
3. 从 `state` 消息到画面变化 ≤ 100ms；工作态动画稳定 ≥ 55fps。
4. **性能预算**（本机 20 核；换算：单核 30% ≈ 整机 1.5%）

   **实测基准（140px，spike 实测）**：PySide6 带静态缓存 ≈ **34.4% 单核 / 59MB**；Electron ≈ **30.6% 单核 / 361MB**。→ 两条路在真实尺寸下 **CPU 基本打平**（区间重叠 25.7–41.8 vs 22.3–38.9），Electron 唯一劣势是内存 6 倍。注意 Electron 的内存与图标尺寸**无关**（240px→140px 时 353MB→361MB，是 Chromium 固定开销），别指望缩小图标能省内存。

   - **空闲 IDLE**：目标 **< 10% 单核**（≈整机 0.5%）。实测未优化值 ≈30% 单核，必须优化下来。
   - **工作 WORK**：< 35% 单核（≈整机 1.75%）。
   - **关键手段（Electron 必做）**：**空闲态不要挂 CSS 无限动画**。CSS 动画会让合成器按显示器刷新率（本机 120Hz）持续跑，这正是 CPU 降不下来的主因（Electron 240px→140px 时 CPU 几乎不变，就是因为开销由每帧固定成本决定、与像素数无关）。空闲态改为低频 JS 驱动的状态更新（4–10 fps 足以表达"慢呼吸"），或状态不变时直接暂停渲染循环。
   - **内存**：尽力收敛，不设不可达硬指标。可试 `app.disableHardwareAcceleration()`、减粒子、空闲暂停渲染；**如实报告测到的数字与试过的手段——做不到就写做不到，不许谎报达标**。
   - 静态图层缓存（L1 底盘 / L2 刻度环 / L4-L5 静态环不每帧重绘）在 Qt 上实测有效（95.5%→80.7% 单核），Electron 侧用 CSS 合成层（`will-change` / 独立图层）天然获得同等效果。
5. 拖动后重启，图标回到上次位置（±2px）。
6. 杀掉窗口进程，宿主不崩；重启宿主，窗口能自动回来。
7. 闲置 10 分钟不抢焦点、不弹窗、CPU 接近 0。
8. **透明区域不得吃鼠标**：图标圆形之外的点击必须穿透到下层窗口（用 `setMask` 或 `WS_EX_TRANSPARENT`）。

## 9. 原生窗口实现要点（spike 已实测，不是推测）

> 技术栈已定案 **Electron**。9A 是实现方必须遵守的；9B 栈无关；9C 是 Qt 路线的历史证据，除非将来回退否则不用。

### 9A. Electron 路线（当前实现）

1. **测试/取证一律用隐藏窗口**：`show: false` 的 BrowserWindow 仍会离屏渲染，`win.capturePage()` 能拿到正确的 RGBA（实测 480×480、四角 alpha=0、全透明 28.1%）。**开发测试不要显示窗口**——用户明确投诉过弹窗干扰。必须显示真窗口的验证（DWM 合成 / 置顶 / 点击穿透 / 不抢焦点）**单项 ≤ 20 秒、窗口放屏幕角落、测完立即关闭并清理进程**。
2. **点击穿透**：`setIgnoreMouseEvents(true, { forward: true })`，实测 exstyle 由 `0x08200008 [TOPMOST, NOACTIVATE]` → `0x08280028 [TOPMOST, LAYERED, TRANSPARENT, NOACTIVATE]`。目标是**只在图标可绘区域内拦截**、其余穿透（验收第 8 条）。
3. **置顶**：`alwaysOnTop: true` + `setAlwaysOnTop(true, 'screen-saver')`。
4. **不抢焦点**：`focusable: false`（实测 `WS_EX_NOACTIVATE` 在位）。注意这不是"永不前台"的绝对保证——用 `SetForegroundWindow` 强拉仍能拉起来。
5. **`skipTaskbar` 不走 `WS_EX_TOOLWINDOW`**（与 Qt 的 `Qt.Tool` 机制不同），实测主窗口枚举无 TOOLWINDOW 位。要完全不进 Alt-Tab 需额外处理。
6. **`setBackgroundColor` 不会改已渲染页面的背景**——取证要换底色时必须 `loadURL` 重载纯色页。
7. **透明窗不用 `WS_EX_LAYERED`**（基线 exstyle 无该位），靠 DWM 原生合成。
8. **内存是 Electron 的短板**：4 进程（Browser + GPU + Utility + 渲染）实测 353MB，其中 GPU 进程 126–165MB。

### 9B. 栈无关的坑（两条路都要遵守）

9. **DPI**：本机 dpr=2.0，240 逻辑像素 = 480 物理像素。**逻辑坐标与物理坐标不许混用**。多显示器不同 DPI 未验证。
10. **多显示器**：本机只有 1 块屏，未验证。必须做跨屏夹取，不能让窗口跑到屏幕外找不回来。
11. **独占全屏（D3D exclusive）会盖住 topmost 窗口**，压不过它；无边框全屏一般能压住。已知限制，不承诺解决。
12. **生命周期天然收敛**：父进程一死 stdin EOF，子进程应自行退出。
13. **取证坑**：抓屏验证合成效果时，**背景窗口也必须置顶**，否则会被别的应用窗口压住导致误判——这条 Qt 与 Electron 两次都栽过。

### 9C. Qt 路线（历史证据，除非回退否则不用）

若将来回退到 PySide6：`paintEvent` 必须先 `CompositionMode_Source` 清屏再切回 `SourceOver`（否则拖影黑底）；窗口标志 `FramelessWindowHint | WindowStaysOnTopHint | Tool` + `WA_TranslucentBackground`（实测 exstyle `0x00080088` → `0x08080088`）；**透明 ≠ 鼠标穿透**，透明像素照样吃点击；静态层用 QPixmap 缓存。完整原型与实测日志见 `spike/`（**2026-09-13 已随仓库保存**：11 个 `.py` 源文件；spike 的 Electron 版原型与运行日志仍留在 temp4，未搬迁）。

## 10. 🚫 测试红线（用户机器不可被干扰 | 硬约束，违反即停工）

> 同类事故已发生两次。第一次：子代理为验证启动流程反复冷启动游戏实例（110–130 秒/次），用户只能自己动手关窗口。第二次（2026-09-12）：成员为验证"真实鼠标拖动"，用 `SetCursorPos` + `mouse_event` **物理拖走了用户的鼠标光标**，用户当场投诉"为什么一直在动我鼠标"。

1. **禁止任何形式的真实输入合成**：`SetCursorPos`、`mouse_event`、`SendInput`、`keybd_event`、`pyautogui`、`SendKeys`、AutoHotkey —— **一律禁止，没有例外**。这些 API 会直接抢占用户的键鼠，不是在测试，是在干扰人。已产出的三个脚本（`mouse-drag.ps1` / `mouse-click.ps1` / `probe-dpi.ps1`）已隔离到 `runtime\electron\test\_QUARANTINE-real-input\`，**不得恢复、不得重写、不得换个名字重来**。
2. **拖动验证走内部路径就够**：`--test-drag` 直接触发 `drag-by` / `drag-end` 分支，与真实拖动**走同一条代码路径**，不需要真的动光标。真实输入的端到端验证由**人在场时手工做**，不由脚本做。
3. **禁止自愈式重试 / 保活 / watchdog**：进程消失 = 人为终止，**不是崩溃**，绝不自动重启。（第一次事故的真正元凶就是启动脚本的保活逻辑把 captain 的关闭当成崩溃、连开三次。）
4. **禁止启动任何重型 GUI 程序**：游戏、模拟器、IDE、大型编辑器一律不碰。用户的日常实例更不要碰。
5. **默认离屏**：所有 GUI/浏览器测试默认隐藏窗口；必须真窗口的验证单次 ≤ 20 秒、放屏幕右下角、测完立即关闭并清理进程。性能数字必须真窗口测（离屏 dpr 与帧率都不同，数字失真数倍），但**能离屏的一律离屏**。
6. 任何新写的测试脚本若需要真实输入或真实窗口，**先向决策层申请，由决策层向用户取得明确许可**；能合并的取证必须合并成一次跑完，不为单项反复触发。
7. **测试/集成脚本 spawn 窗口时必须显式带 `--hidden`**。生产路径默认是**显示图标**（产品就该如此），所以"不弹窗"这件事在测试里**必须由调用方自己保证**，不能依赖默认值。已出过事故：宿主侧第一版 e2e 漏了 `--hidden`，用户屏幕上真的出现了一个置顶图标约 30 秒。窗口侧现已在 e2e 里加了「测试期间日志不得出现 `window shown`」的断言，但**不要把安全寄托在断言上**——任务书里必须写明这条。
